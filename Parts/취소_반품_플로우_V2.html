업무 흐름

위에서 아래로 시간 순서이고, 파란 점선은 동시에 진행되는 흐름, 보라 점선은 반품신청서 조건입니다. 맨 위에서 부품을 구분합니다. 재고 부품은 왼쪽 선으로 주문상세 취소에 합류하고, 매입처 부품만 발송 여부를 탑니다. 회수 취소도 매입처 부품과 재고 부품이 하는 일이 달라 분기한 뒤 회수취소 출고로 합류하고, 되돌릴 때는 회수전으로 복귀해 회수 단계로 다시 들어갑니다. 미입고분은 무조건 입고 처리한 뒤 진행합니다. 취소 시 상태값은 신청전·회수전·입고·취소전이고, 물류팀이 공장에서 회수해 카랑창고에 입고해야 판매 가능해집니다. 발주취소·미차감은 매입처 부품만 확인합니다. 재고 부품은 회수되면 주문 재처리로 끝나고 재판매 프로세스를 타지 않습니다.

반품신청서 회수 반품배송 계산서 취소 재고 판매 가능 판매 불가 동시 진행 신청완료 조건

유형별 상태값 변화

상태값 정의

A. 반품신청서견적팀 · 취소리스트

신청전→신청완료/신청불필요/재판매신청불필요/회수취소신청불필요/null
  • 매입처 부품이 취소 처리되면 기본값 신청전. 재고 부품은 반품신청서가 필요 없어 처음부터 null
  • 매입처에 반품신청서를 작성하면 신청완료. 신청완료 건만 반품배송 진행. 신청서 작성과 물류팀 회수는 동시에 진행될 수 있다
  • 매입처 발주상태가 취소이고 미차감이면 신청불필요. 재고에서 제외하고 종료 — 예외 처리이며 아래 주의 참고
  • 공장이 회수를 취소하면 매입처 부품만 회수취소신청불필요 추가. 부품이 공장에 남아 매입처로 보낼 수 없다 — 부품이 매입처에 있는 신청불필요와 위치가 정반대라 상태값을 분리한다. 회수취소와 동시에 변경하며, 신청완료 이후에도 가능하다. 이미 낸 신청서의 철회는 재판매와 같이 견적팀이 매입처와 직접 처리한다. 재고 부품은 반품신청서가 처음부터 null이므로 그대로 유지
  • 회수완료·입고 상태에서 판매되면 재판매신청불필요 추가 — 자동 선택 또는 사용자 선택. 매입처 부품만 해당하고, 부품이 카랑창고에 있는 반품출고 전까지만 가능하다. 이미 낸 신청서의 철회는 견적팀이 매입처와 직접 처리
  • 신청불필요는 예외 처리입니다. 매입처에서 카랑창고로 출고된 부품이라면 발생하지 않고, 출고 전이라면 발송 전 취소(유형 0)로 걸러집니다. 오프라인 업무에서 뒤늦게 발주취소·미차감이 확인되는 경우를 위한 경로이므로, 취소 시점에 설정된 회수완료 → null 역전과 재고 포함 → 제외 전환을 허용합니다

B. 회수물류팀

회수전→회수중→회수완료/회수취소/null
  • 취소 처리되면 기본값 회수전. 공장에서 회수를 시작하면 회수중
  • 공장에서 회수해 카랑창고로 입고되면 회수완료. 이때부터 판매 가능
  • 재고 부품도 회수 상태는 동일하게 관리한다 (나머지 세 상태값만 null)
  • 회수전·회수중 상태에서 공장이 회수를 취소하면 회수취소 추가. 부품이 공장에 남으므로 카랑창고로 돌아오지 않는다 — 재고에서 회수취소로 출고한다. 매입처 부품은 동시에 반품신청서를 회수취소신청불필요로, 반품배송·계산서 취소를 null로 바꾸고, 재고 부품은 회수 상태만 바뀐다(나머지는 이미 null). 회수완료 이후에는 회수 취소 불가
  • 회수취소를 취소하면 회수전으로 복귀한다. 매입처 부품은 반품신청서 신청전 · 반품배송 입고 · 계산서 취소 취소전로 함께 되돌리고, 재고 부품은 회수만 되돌린다. 재고는 회수취소 출고를 취소해 다시 포함시킨다
  • 신청불필요 건은 매입처에서 카랑창고로 출고되지 않아 회수할 부품이 없으므로 null

C. 반품배송물류팀

입고→출고준비→배송중→배송완료/null
  • 기본값 입고. 다음날 반품하지 않는 부품은 입고 유지
  • 신청완료 부품 중 다음날 반품할 부품은 출고준비. 이때부터 판매 불가
  • 반품배송이 출발하면 배송중, 도착하면 배송완료
  • 재판매·신청불필요·회수취소 건과 재고 부품은 null

D. 계산서 취소회계팀

취소전→취소요청중→취소완료/null
  • 매입처 부품의 기본값은 취소전. 재고 부품은 매입처 계산서가 없어 처음부터 null
  • 반품배송완료 이후 취소요청중
  • 매입처의 계산서 취소를 확인하면 취소완료. 재고에서 반품완료로 출고
  • 재판매·신청불필요·회수취소 건과 재고 부품은 null이며 회계팀 목록에서 제외. 회수취소는 매입처에서 차감된 상태로 두므로 계산서 취소를 하지 않는다

개발 반영 사항

  • 진입먼저 매입처 부품 / 재고 부품을 구분한다. 재고 부품은 매입처 발송 여부와 관계없이 주문상세 취소로 간다
  • 주문상세 · 취소발송 전 삭제는 매입처 부품만. 재고 부품은 유형 0으로 가지 않는다
  • 주문상세 · 취소두 경로 모두 미입고분은 무조건 카랑창고 입고 처리 후 다음 단계로 진행. 취소와 동시에 재고 전환
  • 주문상세 · 취소취소 시 상태값은 신청전 / 회수전 / 입고 / 취소전 — 기존과 동일하게 유지한다. 주문상태에 따라 회수완료로 앞당기지 않는다
  • 취소리스트발주취소·미차감 확인과 신청불필요는 매입처 부품만. 재고 부품은 자사 재고이므로 신청서·차감 여부를 확인하지 않는다
  • 취소리스트반품신청서 상태 5종 + null: 신청전 / 신청완료 / 신청불필요 / 재판매신청불필요 / 회수취소신청불필요 / null(재고 부품)
  • 취소리스트신청불필요 선택 시 재고에서 제외, 회수·반품배송·계산서 취소 null, 각 팀 목록에서 제외
  • 취소리스트 · 예외신청불필요는 예외 경로다. 매입처 → 카랑창고 출고 건에서는 발생하지 않는다. 이미 설정된 회수완료를 null로 되돌리고 재고 포함을 제외로 바꾸는 역전을 허용한다
  • 재고 · 판매판매 가능 조건은 회수완료 + 입고 (출고준비 전)
  • 재고 · 판매판매 시 재판매신청불필요 자동 선택 또는 사용자 선택, 반품배송·계산서 취소 null
  • 재고 · 판매재판매는 매입처 부품 전용이다. 부품이 카랑창고에 있는 반품출고 전까지만 가능하고, 반품출고 이후에는 재판매할 수 없다
  • 재고 · 판매재고 부품은 재판매 프로세스를 타지 않는다. 회수완료되면 주문 재처리(재고 환원)로 종료
  • 주문상세 · 취소재고 부품은 반품신청서 · 반품배송 · 계산서 취소가 모두 불필요하므로 취소 시점부터 세 상태값을 null로 두고 견적팀·물류팀(반품배송)·회계팀 목록에서 제외한다. 회수 상태만 관리
  • 물류출고준비 전환은 신청완료 건만 가능, 출고준비부터 판매 불가
  • 공통 원칙매입처로 반품하지 않는 건은 이후 진행하지 않는 상태값을 null로 두고 해당 팀 목록에서 제외한다 — 신청불필요은 회수·반품배송·계산서 취소, 재판매신청불필요와 회수취소신청불필요는 반품배송·계산서 취소(회수는 회수취소로 남김), 재고 부품은 반품신청서·반품배송·계산서 취소
  • 물류 · 회수회수 상태값에 회수취소를 추가한다. 회수전·회수중에서만 선택 가능하고 회수완료 이후에는 불가. 선택 시 물류팀 회수 목록에서 제외
  • 회수취소매입처 부품은 회수취소와 동시에 반품신청서를 회수취소신청불필요로 변경, 재고 부품은 null 유지. 반품배송·계산서 취소는 null (매입처 차감분은 그대로 둔다)
  • 회수취소 · 견적신청완료 이후에도 회수 취소가 가능하다. 이미 매입처에 제출한 반품신청서의 철회는 견적팀이 매입처와 직접 처리하고, 시스템은 상태값만 관리한다 (재판매와 동일)
  • 회수취소 · 되돌리기회수취소를 취소하면 회수 상태를 회수전으로 복귀시킨다. 매입처 부품은 반품신청서 신청전 · 반품배송 입고 · 계산서 취소 취소전로 함께 되돌리고, 재고 부품은 회수만 되돌린다. 회수취소 출고를 취소해 재고에 다시 포함시킨다
  • 회수취소 · 재고재고에서 회수취소 사유로 출고해 제외한다. 신청불필요(매입처 미출고) 출고와 사유를 구분해서 남긴다 — 상태값도 분리되어 있으므로 집계가 섞이지 않는다
  • 회계 · 재고계산서 취소완료 시 재고에서 반품완료로 출고
